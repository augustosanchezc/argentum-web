¿Qué es Argentum Online?

AO es un MMORPG 2D (juego de rol masivo en línea) con vista cenital y estética de pixel-art medieval-fantástico.

  • Te creás un personaje (raza + clase)
  • Subís niveles matando monstruos y haciendo misiones
  • Conseguís oro, items y hechizos
  • Peleás contra otros jugadores (PvP)
  • Te unís a clanes, hacés guerras, comerciás

📌 Datos clave

  • Origen: Argentina, 1999
  • Creador: Pablo "Gulfas Morgolock" Marquez
  • Lenguaje original: Visual Basic 6
  • Licencia: Open Source desde 2003
  • Hito: Primer MMORPG de Latinoamérica
  • Mundo: ~291 mapas conectados

📜 Historia rápida

1999 Pablo Márquez ("Gulfas Morgolock") y Fernando Testa lanzan AO en Argentina, basado en ORE v0.4 de Baronsoft.
2001 Tras un año ininterrumpido online, explota en popularidad. Servidores llenos.
2003 HITO Liberan el código fuente bajo GNU GPL. Cualquiera puede crear su servidor.
2007 Implementan protocolo binario sobre TCP. 550 conexiones simultáneas con ping de 62ms.
2010-2020 Decenas de forks, servidores piratas y reescrituras (Java, C++, web). Comunidad fragmentada.
2020+ AO20 emerge como fork canónico moderno, con mantenimiento activo y entrada en Steam.
2026 Cuatro ecosistemas activos en GitHub. Proyectos web con PixiJS retoman fuerza.

🗺️ El mundo de Argentum

El mundo está dividido en una grilla de ~291 mapas, cada uno de 100×100 tiles. Los personajes caminan tile-por-tile (estilo grilla, no movimiento libre).

🌲 Tipos de zonas

  • Ciudades — comercio, banco, sacerdote
  • Bosques y praderas — leveleo bajo
  • Dungeons — mazmorras con monstruos fuertes
  • Zonas seguras (verdes) — sin PvP
  • Zonas inseguras (rojas) — PvP libre
  • Mar — navegable con barcos
  • Catacumbas, Yulminaki, Sherwood, Helheim...

Cada mapa es un archivo binario (.map, .inf, .dat) con tiles, triggers, NPCs y objetos.

🧝 Razas y ⚔️ Clases

Balanceado. Sin debilidades pero sin grandes fortalezas. Ideal para empezar.

🧝 Elfo

Ágiles e inteligentes. Mejores como cazadores, magos y arqueros.

Tanques. Mucha fuerza y constitución, baja agilidad y carisma.

⚔️ Combate y muerte

Cómo se pelea

  • Cuerpo a cuerpo: click en enemigo (tile adyacente)
  • Magia: seleccionás hechizo + objetivo
  • Distancia: arco/proyectil con línea de visión
  • Daño = ataque + arma + skill − defensa enemigo + dado

Qué pasa al morir

  • Te convertís en fantasma 👻
  • Tirás todo el inventario al suelo (items + oro)
  • Necesitás un clérigo o sacerdote para revivir
  • Si te mata otro player → ese gana karma negativo (ciudadano) o se vuelve criminal
  • Criminales no pueden entrar a ciudades (Guardias atacan)

👑 Game Masters (GMs)

Personal del servidor con poderes especiales. Tres rangos jerárquicos:

🪶 Consejero

Rol básico. Puede teleportar, ver invisibles, mutear.

⚜️ Semidiós

Comandos intermedios. Puede banear, encarcelar, generar items.

👑 Dios

Acceso total. Reinicia mapas, aplica updates, manipula NPCs.

Stack original

🖥️ Servidor

  • Lenguaje: Visual Basic 6.0 (1998)
  • Networking: sockets TCP/IPv4 bloqueantes
  • Protocolo: binario (desde 0.11.6)
  • Persistencia: archivos planos (.dat, .ini, .chr)
  • Game loop: single-threaded con timers de Windows

🎮 Cliente

  • Lenguaje: Visual Basic 6.0
  • Render: DirectDraw (DirectX 7)
  • Tiles: 32×32 px sprites
  • Audio: DirectSound + MIDI
  • Mapas: archivos .map + .inf

💡 Curiosidad: el juego sigue funcionando en Windows modernos gracias a capas de compatibilidad y a forks que actualizaron las dependencias DirectX.

Cómo se comunican cliente y servidor

Antes (texto)

Hasta 0.11.5 los mensajes eran texto plano sobre TCP. Verboso y lento.

;TALK Hola que tal
;MOVE NORTH
;ATTACK 4523

Ahora (binario)

Desde 0.11.6: cada mensaje empieza con un byte de OpCode y luego campos empaquetados (byte, int16, string).

[0x01][len: u16][texto]    // TALK
[0x06][dir: u8]            // MOVE
[0x0A][targetID: u16]      // ATTACK

Con el protocolo binario el servidor pudo manejar 550 conexiones simultáneas con ping de 62ms.

La licencia: AGPL-3.0

"GNU Affero General Public License v3" — una licencia libre con un giro:

  • ✅ Podés usar, modificar y vender el código
  • ⚠️ Si lo ofrecés como servicio en red, los usuarios tienen derecho a recibir tu código modificado
  • ⚠️ Cualquier obra derivada también debe ser AGPL

⚠️ Importante para proyectos derivados

Si tu servidor de AO está online y la gente se conecta, tenés que publicar tu código. No podés cerrarlo como SaaS propietario.

Esto es lo que se llama "cerrar el agujero del ASP" y es la diferencia clave con la GPL clásica.

🚀 Nuestro proyecto

Reescritura web moderna del servidor AO. Decisiones técnicas iniciales:

🖥️ Backend

  • Node.js + TypeScript
  • WebSocket binario (MessagePack)
  • PostgreSQL + Redis
  • Game loop a tick fijo (10–20 Hz)
  • Protocolo propio (no compatible con clientes VB6)

🎮 Frontend

  • PixiJS v8
  • TypeScript + Vite
  • HUD con preact/lit
  • Mobile-first
  • Render Canvas/WebGL

🎯 Resumen
